# 库存管理模块完整重写设计

## 目标

完整重写库存管理模块的界面、业务规则和数据访问代码，同时保持客户积分、报价、邮件、视频等其他模块不变，并无损兼容现有库存数据。

## 方案选择

### 采用方案：模块化重写并兼容现有表结构

将当前集中在 `app.py` 和多个数据库管理器中的库存代码拆分为独立模块，以统一服务层承载业务规则，以仓储接口隔离数据库实现，以专用 Streamlit 页面承载交互。

该方案保留现有 `inventory_items`、`inventory_transactions`、`inventory_fields` 表和历史数据，只添加向后兼容的可空字段与索引，不重建数据库。

### 未采用方案：只修补现有页面

只修补下拉框和重复编号错误改动较小，但无法解决 `show_inventory()` 过大、业务规则散落、数据库代码重复和缺少自动化测试的问题，不符合完整重写目标。

### 未采用方案：重新设计全部数据库表

完全规范化物品、类别、位置和选项表可提供独立字典管理，但需要复杂数据迁移，增加现有生产数据风险。本轮不引入独立字典表，历史选项继续从库存记录聚合。

## 保留的数据与兼容性

- 保留所有现有库存物品。
- 保留所有出入库记录。
- 保留所有自定义字段定义和物品自定义字段值。
- 继续支持 MySQL、PostgreSQL 和 SQLite。
- 现有物品默认处于启用状态。
- 数据库迁移只允许增加字段、索引或约束，不删除现有列和数据。

## 模块结构

### `modules/inventory/models.py`

定义库存物品、出入库命令、历史选项和业务错误等领域对象。输入在进入数据库前统一清理和校验。

### `modules/inventory/field_values.py`

负责历史选项标准化、搜索选项构建和“新输入值优先、历史选择回退”的最终值解析。

### `modules/inventory/repository.py`

定义库存仓储接口和现有数据库管理器适配器。页面和服务层不直接拼接 SQL。

### `modules/inventory/service.py`

集中处理以下规则：

- 编号由用户手动输入且必须唯一。
- `title` 必填。
- `title`、`title类别`、`存放位置` 支持历史值搜索和新值输入。
- 出库数量不得超过当前库存。
- 入库和出库数量必须为正整数。
- 有历史记录的物品只能归档，不能硬删除。
- 无历史记录的物品可彻底删除。
- 数据库异常转换为明确的中文业务错误。

### `modules/inventory/ui.py`

负责库存页面渲染，拆分为概览、库存列表、物品表单、出入库操作、记录查询和字段管理组件。

### `app.py`

只保留库存页面入口调用，不继续维护大段库存业务代码。

## 页面设计

### 库存列表

顶部依次显示：

1. 搜索框。
2. 类别筛选。
3. 位置筛选。
4. 库存状态筛选。
5. 新增物品按钮。

统计区显示物品种类、库存总量、低库存和零库存数量。

列表按物品展示编号、名称、类别、位置、当前库存和状态，并提供入库、出库、编辑、归档操作。归档物品默认隐藏，可通过筛选查看。

### 新增和编辑物品

表单字段顺序为：

1. 编号。
2. `title`。
3. `title类别`。
4. 存放位置。
5. 初始数量。
6. 备注。
7. 自定义字段。

`title`、`title类别`、存放位置均同时提供：

- 可搜索的历史值下拉框。
- 可选的新值输入框。

用户输入新值时使用新值；未输入新值时使用历史选择。保存成功后，新值通过历史数据查询自动进入下次选项。

没有历史值时，页面允许直接输入新值，不显示不可用的“➕ 新增...”流程。

### 出入库

入库和出库操作以当前物品为上下文，显示当前库存、数量、备注和操作人。

- 入库数量必须大于零。
- 出库数量必须大于零且不得超过当前库存。
- 操作成功后库存和记录在同一事务中更新。
- 失败时库存和记录均不发生变化。

### 出入库记录

支持按编号、名称、操作类型和日期筛选，展示操作时间、物品、类型、数量、操作前库存、操作后库存、备注和操作人。

现有历史记录没有库存快照时允许为空；新记录写入快照字段。

### 字段管理

保留自定义字段功能，增加字段名称和标识校验。已被物品使用的字段默认不允许直接删除，避免历史数据失去含义。

## 编号规则

- 编号由用户手动输入。
- 保存前主动查询是否重复。
- 编辑当前物品时允许保留原编号。
- 重复时显示“编号已存在，请输入其他编号”。
- 不向用户显示数据库约束名、SQL 或英文驱动错误。

## 历史值规则

- 数据源为启用和归档物品的历史非空值。
- 统一去除首尾空白。
- 过滤空字符串和纯空白值。
- 大小写保持原样。
- 相同文本只显示一次，并稳定排序。
- 新输入值优先于历史选择。
- 位置与名称、类别使用完全相同的规则。

## 删除与归档规则

- 有任何出入库记录的物品只能归档。
- 归档物品不出现在默认库存列表和新增出入库选择中。
- 归档物品的历史记录继续可查询和导出。
- 没有出入库记录的物品可在二次确认后彻底删除。
- 归档物品可以恢复启用。

## 数据库变更

在兼容现有数据的前提下增加：

- `inventory_items.is_active`，默认值为真。
- `inventory_items.updated_at`，记录最后修改时间。
- `inventory_transactions.stock_before`，允许为空。
- `inventory_transactions.stock_after`，允许为空。
- 编号唯一索引继续保留。
- 类别、位置、标题和启用状态增加查询索引时，不改变现有字段含义。

所有数据库实现必须具备等价行为。SQLite 初始化和远程数据库初始化均执行幂等迁移。

## 错误处理

定义稳定的业务错误类型：

- 编号重复。
- 必填字段为空。
- 数量非法。
- 库存不足。
- 物品不存在或已归档。
- 有历史记录，不能彻底删除。
- 数据库操作失败。

页面只显示中文业务提示；详细异常保留在日志中。

## 测试策略

### 单元测试

- 历史值清洗、去重、排序。
- 新输入值覆盖历史选择。
- 编号和必填字段校验。
- 出库库存不足校验。
- 删除与归档判断。

### SQLite 集成测试

- 保存新值后历史选项可查询。
- 重复编号在写入前被拒绝。
- 入库和出库原子更新库存与记录。
- 库存不足时库存和记录均不变化。
- 有记录物品归档，无记录物品彻底删除。
- 现有旧表可通过幂等迁移继续读取。

### 静态验证

- 运行库存测试。
- 运行全部相关 Python 测试。
- 对 `app.py` 和库存模块执行语法编译。
- 检查 Git diff 中不存在密钥、数据库密码或生成文件。

## 验收标准

1. 现有库存物品和出入库记录无损显示。
2. 用户手动输入唯一编号；重复编号显示中文提示。
3. `title`、`title类别`、存放位置可搜索历史值，也可输入新值。
4. 新值保存后自动出现在下一次历史选项中。
5. 出库超过库存时无法提交，库存不会变为负数。
6. 入库和出库记录与库存更新保持原子一致。
7. 有记录物品可归档和恢复，但不能硬删除。
8. 页面不再显示原始 SQL 或数据库英文错误。
9. 库存页面代码从 `app.py` 拆出，其他业务模块行为不变。
10. MySQL、PostgreSQL 和 SQLite 的库存行为一致。

## 非目标

- 不重写整个客户积分系统。
- 不修改客户积分、报价、邮件、发票或视频模块。
- 不创建独立的类别或位置管理后台。
- 不自动生成库存编号。
- 不改变现有登录和权限体系。
