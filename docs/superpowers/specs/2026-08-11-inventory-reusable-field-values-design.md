# 库存可复用字段值设计

## 目标

修复库存新增和编辑表单中“新增历史值”无法使用的问题，并让 `title`、`title类别`、`存放位置` 三个字段支持：

- 直接选择以前保存过的非空值。
- 输入一个新值并保存当前库存物品。
- 保存成功后，新值在下一次新增或编辑时自动进入可选列表。

## 当前问题

当前实现把“➕ 新增...”选项和条件文本输入框放在 `st.form` 内。Streamlit 表单中的控件变化不会立即触发页面重跑，因此用户选择“➕ 新增...”后，新的文本输入框无法及时出现，导致新增值流程不可用。

此外，当前数据库只提供 `category` 和 `location` 的历史值查询，`title` 仍然是普通文本输入框。

## 推荐方案

新增一个独立、可测试的字段值解析模块，统一处理历史选项、清洗和最终取值。界面不再依赖“选择新增后动态显示输入框”，而是在表单中同时提供：

1. 历史值下拉框。
2. 可选的新值输入框。

保存时采用以下优先级：

1. 新值输入框存在非空内容时，保存清理后的新值。
2. 新值为空时，保存下拉框中选择的历史值。
3. 两者均为空时，非必填字段保存空字符串；`title` 按现有规则提示必填错误。

这样不依赖表单内的即时刷新，并兼容项目声明的 `Streamlit >=1.36.0`。

## 数据来源

历史选项继续从 `inventory_items` 表实时聚合，不新增配置表或数据库迁移：

- `title`：查询所有非空、不重复的 `title`。
- `title类别`：查询所有非空、不重复的 `category`。
- `存放位置`：查询所有非空、不重复的 `location`。

查询结果去除首尾空白、过滤空值、去重并稳定排序。保存新库存物品或编辑现有物品后，页面重跑，最新值自然进入下一次查询结果。

## 界面行为

### 快速新增物品

`title`、`title类别`、`存放位置` 分别显示历史值下拉框和“输入新值”文本框。

- 没有历史值时，下拉框显示“暂无历史值”。
- 用户可不操作下拉框，直接输入新值。
- 新值输入框中的非空内容覆盖下拉选择。
- `title` 的最终值为空时禁止提交。

### 编辑物品

编辑时，下拉框默认选择当前物品的值；如果当前值不在历史列表中，则临时加入选项列表。

- 用户可选择其他历史值。
- 用户也可输入新值覆盖下拉选择。
- 留空新值不会清除当前选择。
- `title` 仍为必填字段。

## 代码边界

- `modules/inventory_field_values.py`：负责历史选项标准化、编辑选项构建和最终值解析。
- `modules/db_manager.py`：为 MySQL、PostgreSQL 和 SQLite 增加 `get_distinct_titles()`，并保持三个数据库实现一致。
- `modules/pg_database.py`：增加 PostgreSQL 原生的 `title` 历史值查询。
- `app.py`：替换当前不可用的“➕ 新增...”条件输入交互，调用统一解析逻辑。
- `tests/test_inventory_field_values.py`：覆盖新值优先、历史值回退、空值处理、去重排序和当前编辑值保留。
- `tests/test_inventory_db_values.py`：使用 SQLite 验证保存后的 `title`、`category`、`location` 会出现在历史选项中。

## 错误处理

- 历史值查询失败时，表单仍允许直接输入新值，不阻断库存新增和编辑。
- 数据库存储失败沿用当前错误提示，不吞掉保存异常。
- 历史值中的空字符串和纯空白内容不显示在下拉列表。
- 新输入值保存前统一执行首尾空白清理。

## 验收标准

1. 首次输入新的 `title`、`title类别`、`存放位置` 并保存成功。
2. 页面刷新后，三个新值均出现在对应历史下拉列表中。
3. 不输入新值时，可以直接选择历史值并保存。
4. 同时选择历史值并输入新值时，以新值为准。
5. 编辑库存物品时默认保留当前值，并可切换为历史值或新值。
6. MySQL、PostgreSQL 和 SQLite 管理器均提供一致的历史值查询接口。
7. 新增的单元测试通过，`app.py` 和相关模块通过 Python 语法检查。

## 非目标

- 不新增独立的固定选项管理页面。
- 不新增数据库表或迁移。
- 不支持单独删除历史选项；历史值随库存数据实时产生。
- 不修改现有出入库数量调整、导出或自定义字段功能。
